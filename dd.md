# BarkFluff Client — Дизайн-документ UI/UX

> Описание экранов и пользовательских сценариев клиентского приложения BarkFluff.
> Документ является платформонезависимым — каждый клиент адаптирует описанные экраны под свою платформу, сохраняя общую логику и последовательность.

---

## 1. Экран приветствия (Welcome)

Отображается **один раз** при первом запуске приложения.

### Содержание

- Иконка приложения (логотип BarkFluff)
- Название приложения — **BarkFluff**
- Слоган — *«Мессенджер для твоей стаи»*
- Краткое описание (2–3 строки): назначение приложения, акцент на приватность и децентрализацию
- Кнопка **«Начать»** — переход к выбору сервера

### Дополнительно (рекомендуется)

- Ссылки в футере: «О проекте», «Политика конфиденциальности», «Справка»
- Анимация логотипа при появлении экрана (платформозависимо)

---

## 2. Защищённое хранение данных

До отображения основного окна с чатами и user-specific информацией клиент **обязан** организовать защищённое хранение чувствительной информации.

### Принципы

| Аспект                            | Описание                                                                                                                |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Определение чувствительных данных | Клиент самостоятельно решает, какие данные считать чувствительными (токены, ключи шифрования, пароли и т.д.)            |
| Способ хранения                   | Платформозависимый, но обязан быть работоспособным на любой поддерживаемой вариации платформы                           |
| Взаимодействие с пользователем    | Клиент сам определяет, требуется ли участие пользователя (например, создание мастер-пароля, биометрия)                  |
| Момент инициализации              | Если взаимодействие с пользователем необходимо — оно происходит **до** первого сохранения чувствительных данных на диск |

### Текущие реализации

| Платформа     | Механизм                                         |
| ------------- | ------------------------------------------------ |
| Android       | `EncryptedSharedPreferences` (AndroidX Security) |
| WPF (Windows) | DPAPI / Windows Credential Manager               |
| Linux         | libsecret / keyring                              |
| macOS / iOS   | Keychain Services                                |

## 3. Экран выбора сервера (Select Server)

### Содержание

- **Список публичных серверов** — загружается с `https://navigator.barkfluff.com:443`
- **Поле ручного ввода** — beacon-адрес сервера для подключения к приватным/self-hosted инстансам
- Кнопка **«Подключиться»**

### Карточка сервера в списке

Каждый сервер отображает:

| Поле          | Описание                            |
| ------------- | ----------------------------------- |
| Публичное имя | Отображаемое название сервера       |
| Описание      | Краткое описание сервера            |
| @servername   | Уникальный идентификатор сервера    |
| Локация       | Географическое расположение сервера |

> Поле количества пользователей **устарело** и не отображается.

### Дополнительно (рекомендуется)

- Информационный баннер о возможности развернуть собственный сервер

- Запоминание последнего использованного сервера

## 4. Экран входа (Login)

### Содержание

- Логотип BarkFluff + название текущего сервера
- Заголовок — *«Добро пожаловать»*

### Поля ввода

- **Логин или Email** — текстовое поле
- **Пароль** — поле с переключателем видимости

### Кнопки и ссылки

| Элемент         | Действие                                     |
| --------------- | -------------------------------------------- |
| **Войти**       | Основная кнопка — отправка формы авторизации |
| Сбросить пароль | Переход на экран восстановления пароля       |
| Создать аккаунт | Переход на экран регистрации                 |
| Сменить сервер  | Возврат на экран выбора сервера              |

### OTP-подтверждение (2FA)

Если сервер требует двухфакторную аутентификацию, после успешной проверки логина/пароля отображается:

- 6 отдельных полей ввода для OTP-кода
- Автоматический переход фокуса между полями
- Автоматическая отправка при заполнении всех 6 цифр
- Поддержка вставки кода из буфера обмена

### QR-код для быстрого входа (только десктоп)

На десктопных клиентах дополнительно отображается QR-код для **Fast Auth** — быстрого входа путём сканирования с мобильного устройства, на котором уже выполнен вход.

## 5. Экран восстановления пароля (Password Reset)

Многошаговый процесс сброса пароля с визуальным индикатором прогресса.

### Визуальный индикатор

Пошаговый индикатор в виде пронумерованных кружков (1 — 2 — 3 — ✓), соединённых линиями. Активный шаг выделяется цветом, пройденные шаги отмечаются как завершённые, будущие шаги остаются неактивными.

---

### Шаг 1: Идентификация пользователя

**Заголовок:** «Восстановление пароля»
**Подзаголовок:** «Следуйте инструкциям для сброса пароля»

- Описание: *«Введите email или имя пользователя»*
- Текстовое поле ввода email / username
- Кнопка **«Отправить код»** — инициирует отправку 6-значного кода на привязанный email
- Ссылка **«Вернуться к входу»** — возврат на экран логина

**Валидация:**

- Проверка формата email (если введён email)
- Проверка минимальной длины (если введён username)
- Отображение ошибки, если аккаунт не найден

---

### Шаг 2: Подтверждение кода

**Заголовок:** «Введите код подтверждения»
**Подзаголовок:** «Мы отправили 6-значный код на ваш email»

- 6 отдельных полей ввода (по одной цифре)
- Автоматический переход фокуса при вводе цифры
- Поддержка удаления (Backspace возвращает фокус на предыдущее поле)
- Поддержка вставки полного кода из буфера обмена
- Кнопка **«Подтвердить код»**
- Ссылка **«Отправить код повторно»** — повторная отправка с задержкой (cooldown)

**Валидация:**

- Принимаются только цифры
- Код должен состоять из 6 символов
- Отображение оставшихся попыток при неверном вводе

---

### Шаг 3: Создание нового пароля

**Заголовок:** «Создайте новый пароль»

- Поле **«Новый пароль»** — с переключателем видимости
- Индикатор сложности пароля (ProgressBar) с цветовой шкалой:
  - Красный → Оранжевый → Жёлтый → Зелёный
- Текстовая оценка сложности: «Слабый» / «Средний» / «Хороший» / «Отличный»

**Чеклист требований к паролю** (каждый пункт помечается ✓ при выполнении):

| Требование          | Описание                       |
| ------------------- | ------------------------------ |
| Минимум 8 символов  | Базовая длина                  |
| Заглавные буквы     | Хотя бы одна                   |
| Строчные буквы      | Хотя бы одна                   |
| Цифры               | Хотя бы одна                   |
| Специальные символы | Хотя бы один (!@#$%^&* и т.д.) |

- Поле **«Подтвердите пароль»** — повторный ввод
- Текст совпадения/несовпадения паролей
- Кнопка **«Сохранить новый пароль»**

**Рекомендации** (информационный блок):

- Используйте комбинацию букв разного регистра
- Добавьте цифры и специальные символы
- Не используйте личные данные в пароле

---

### Шаг 4 (финал): Успешная смена пароля

- Иконка успеха (галочка в зелёном круге)
- Заголовок: *«Пароль успешно изменён!»*
- Подзаголовок: *«Теперь вы можете войти с новым паролем»*
- Кнопка **«Вернуться к входу»** — переход на экран логина

---

### Логика работы сброса пароля (Backend)

Процесс сброса пароля поддерживает два сценария:

#### Сценарий 1: Установка пароля (пароль отсутствует)

Если у пользователя **нет установленного пароля** (хеш пароля в базе пустой):

- Пользователь может установить пароль, имея только токен авторизации
- Поле старого пароля **не требуется**
- Используется эндпоинт `SetPassword` без параметра `old_password`

#### Сценарий 2: Сброс пароля (пароль существует)

Если у пользователя **есть пароль** (хеш существует в базе):

1. **Запрос сброса** (`ResetPassword`)
   
   - Пользователь вводит email или username
   - На привязанную почту отправляется 6-значный код подтверждения
   - Код действителен в течение ограниченного времени

2. **Подтверждение сброса** (`ConfirmResetPassword`)
   
   - Пользователь вводит полученный код
   - После успешной проверки кода:
     - **Хеш старого пароля удаляется** из базы
     - Генерируются новые access_token и refresh_token
   - Запрос сброса помечается как использованный (одноразовый)

3. **Установка нового пароля** (`SetPassword`)
   
   - Поскольку хеш удалён, поле старого пароля **не требуется**
   - Пользователь вводит только новый пароль

4. **Уведомление**
   
   - После успешной смены пароля на email отправляется уведомление
   - Уведомление содержит: IP-адрес, устройство, ОС, местоположение, время

#### Важные особенности

- Код сброса можно использовать **только один раз**
- После подтверждения кода старый пароль **навсегда теряет актуальность**
- Уведомление о смене пароля отправляется только при изменении существующего пароля (не при первичной установке)

---

### Смена пароля в настройках (Change Password)

**Важно:** Существует два различных сценария работы с паролем:

| Сценарий | Контекст | Метод | UI |
|----------|----------|-------|-----|
| **Сброс пароля** | Пользователь **забыл пароль**, не авторизован | Через код на email | Отдельный экран (ResetPasswordActivity) |
| **Смена пароля** | Пользователь **авторизован**, в настройках безопасности | Через код на email + новый пароль | Модалка в SecuritySettingsActivity |

---

#### Смена пароля в настройках безопасности (для авторизованных пользователей)

**Контекст:** Пользователь находится в настройках безопасности, хочет сменить пароль.

**Recommended Flow (через код на email):**

1. Пользователь нажимает «Сменить пароль» в настройках безопасности
2. Открывается модальное окно с 3 шагами:
   - **Шаг 1:** Нажатие «Отправить код на почту» → код отправляется на привязанный email
   - **Шаг 2:** Ввод 6-значного кода → подтверждение кода
   - **Шаг 3:** Ввод нового пароля + подтверждение → сохранение
3. После подтверждения кода хеш старого пароля **удаляется** из базы
4. Новый пароль устанавливается **без ввода старого**
5. Отправка уведомления на email об изменении пароля

**Требования к паролю:**

| Требование | Описание |
|------------|----------|
| Минимальная длина | 6 символов |
| Подтверждение | Новый пароль должен совпадать с подтверждением |

**UI модалки:**

- Заголовок: «Смена пароля»
- Индикатор шага (Шаг 1/3 → 2/3 → 3/3)
- **Шаг 1:** Кнопка «Отправить код на почту»
- **Шаг 2:** Поле ввода 6-значного кода, кнопка «Подтвердить код»
- **Шаг 3:** Поля «Новый пароль» + «Подтвердите пароль», кнопка «Сохранить новый пароль»
- Валидация в реальном времени:
  - Проверка длины кода (6 цифр)
  - Проверка длины нового пароля (≥ 6 символов)
  - Проверка совпадения паролей
- Toast-уведомления об ошибках/успехе

**Логика работы (Backend):**

1. **Запрос сброса** (`ResetPassword`)
   - Генерируется `resetId` для данной сессии
   - На привязанный email отправляется 6-значный код
   - Код действителен в течение ограниченного времени

2. **Подтверждение сброса** (`ConfirmResetPassword`)
   - Пользователь вводит код
   - После успешной проверки:
     - **Хеш старого пароля удаляется** из базы
     - Генерируются новые access_token и refresh_token
   - `resetId` помечается как использованный

3. **Установка нового пароля** (`SetPassword`)
   - Поскольку хеш удалён, поле старого пароля **не требуется**
   - Передаётся только `resetId` и новый пароль

4. **Уведомление**
   - На email отправляется уведомление об изменении пароля

---

#### Сброс пароля (для неавторизованных пользователей)

**Контекст:** Пользователь забыл пароль, находится на экране входа.

**Flow:**

1. Пользователь нажимает «Сбросить пароль» на экране входа
2. Открывается отдельный экран сброса пароля (ResetPasswordActivity)
3. Многошаговый процесс (3 шага + успех):
   - **Шаг 1:** Ввод email/username → отправка кода
   - **Шаг 2:** Ввод 6-значного кода из email
   - **Шаг 3:** Создание нового пароля (без старого!)
   - **Успех:** Сообщение об успешной смене пароля

**Особенности:**

- После подтверждения кода хеш старого пароля **удаляется** из базы
- Новый пароль устанавливается **без ввода старого**
- Код подтверждения: 6 цифр, отправляется на привязанный email
- После подтверждения кода выдаются новые access_token и refresh_token

**Логика работы сброса пароля (Backend):**

1. **Запрос сброса** (`ResetPassword`)
   - Пользователь вводит email или username
   - На привязанную почту отправляется 6-значный код подтверждения
   - Код действителен в течение ограниченного времени

2. **Подтверждение сброса** (`ConfirmResetPassword`)
   - Пользователь вводит полученный код
   - После успешной проверки кода:
     - **Хеш старого пароля удаляется** из базы
     - Генерируются новые access_token и refresh_token
   - Запрос сброса помечается как использованный (одноразовый)

3. **Установка нового пароля** (`SetPassword`)
   - Поскольку хеш удалён, поле старого пароля **не требуется**
   - Пользователь вводит только новый пароль

4. **Уведомление**
   - После успешной смены пароля на email отправляется уведомление
   - Уведомление содержит: IP-адрес, устройство, ОС, местоположение, время

---

#### Сравнение двух сценариев

| Характеристика | Смена пароля (в настройках) | Сброс пароля (с экрана входа) |
|----------------|-----------------------------|-------------------------------|
| **Контекст** | Пользователь авторизован | Пользователь не авторизован |
| **Требует старый пароль** | ❌ Нет | ❌ Нет |
| **Требует код на email** | ✅ Да | ✅ Да |
| **UI** | Модалка с 3 шагами | Отдельный экран с 3 шагами |
| **Навигация** | Из SecuritySettingsActivity | Из LoginActivity |
| **Метод GrpcManager** | `resetPassword()`, `confirmResetPassword()`, `setPasswordAfterReset()` | `resetPassword()`, `confirmResetPassword()`, `setPasswordAfterReset()` |

## 6. Экран регистрации (Create Account)

Многошаговый мастер создания аккаунта. Всего **9 шагов** с визуальным индикатором прогресса (текст «Шаг X из 9» + ProgressBar).

### Общие элементы

- Логотип BarkFluff + название сервера (в шапке)
- Индикатор прогресса: текст + полоса прогресса
- Кнопки навигации: **«Назад»** / **«Далее»** (на последнем шаге — **«Создать аккаунт»**)
- Шаги 6, 7, 8 являются **необязательными** и могут быть пропущены (кнопка «Пропустить»)

---

### Шаг 1: Личная информация

**Заголовок:** «Личная информация»

| Поле    | Обязательное | Ограничения                   |
| ------- |:------------:| ----------------------------- |
| Имя     | Да           | 3–40 символов, любые символы  |
| Фамилия | Нет          | До 40 символов, любые символы |

**Подсказки:**

- Имя может содержать любые символы
- Минимальная длина — 3 символа
- Длина имени и фамилии ограничена 40 символами
- Фамилия может отсутствовать

**Валидация в реальном времени** — текст под полем отображает ошибки при вводе.

---

### Шаг 2: Имя пользователя (логин)

**Заголовок:** «Имя пользователя»

| Поле  | Обязательное | Ограничения                               |
| ----- |:------------:| ----------------------------------------- |
| Логин | Да           | До 30 символов: латиница, цифры, `_`, `-` |

**Правила:**

- Допустимые символы: латинский алфавит, цифры, нижнее подчёркивание (`_`) и тире (`-`)
- Максимальная длина — 30 символов
- Автоматическое приведение к нижнему регистру
- Проверка доступности логина на сервере (с debounce ~500 мс)

**Валидация в реальном времени** — отображение статуса доступности.

---

### Шаг 3: Электронная почта

**Заголовок:** «Электронная почта»

| Поле  | Обязательное | Ограничения           |
| ----- |:------------:| --------------------- |
| Email | Да           | Валидный формат email |

**Информация:**

- Почта может использоваться для 2FA
- Почта используется для сброса пароля
- На почту отправляются уведомления о входе

При переходе на следующий шаг на указанный email отправляется код подтверждения.

---

### Шаг 4: Подтверждение почты

**Заголовок:** «Подтверждение почты»

- Поле ввода 6-значного кода подтверждения
- Подсказка: *«Сообщение отправлено на вашу почту»*
- Подсказка: *«Проверьте папку со спамом»*
- Отображение оставшихся попыток при неверном вводе (с предупреждающим цветом)

---

### Шаг 5: Создание пароля

**Заголовок:** «Создание пароля»

Аналогично шагу 3 восстановления пароля:

- Поле **«Пароль»** с переключателем видимости
- Индикатор сложности (ProgressBar с цветовой шкалой)
- Текстовая оценка: «Начните вводить пароль» → «Слабый» → ... → «Отличный»
- Чеклист требований (○ → ✓ при выполнении):
  - Минимум 8 символов
  - Заглавные буквы
  - Строчные буквы
  - Цифры
  - Специальные символы
- Поле **«Подтвердите пароль»**
- Индикатор совпадения/несовпадения

**Подсказки:**

- Используйте комбинацию букв разного регистра
- Добавьте цифры и специальные символы
- Минимальная длина пароля — 8 символов

> Этот шаг является **обязательным** и не может быть пропущен.

---

### Шаг 6: Фото профиля (необязательный)

**Заголовок:** «Фото профиля»

- Область загрузки/обрезки изображения (crop)
- Предпросмотр аватара
- Подсказка: *«Загрузите фото профиля»*
- Возможность пропустить шаг

Реализация кропа платформозависима:

- WPF: встроенный `CropImage` контрол
- Android: библиотека uCrop

## 8. Правила загрузки и сжатия вложений

### Общие ограничения

| Параметр                  | Значение |
| ------------------------- | -------- |
| Максимальный размер файла | 512 МБ   |

### Изображения

**Требования к отправке:**

| Параметр         | Значение             |
| ---------------- | -------------------- |
| Формат           | JPEG / JPG           |
| Макс. размер     | 2 МБ                 |
| Макс. разрешение | 2500 × 2500 пикселей |

**Сжатие на клиенте (рекомендуется):**

- Качество JPEG: **90%**
- Цель: уменьшить размер файла до отправки на сервер

**Сжатие на сервере (принудительное):**

Если клиент отправляет изображение, не соответствующее требованиям, сервер применяет автоматическую обработку:

| Правило                                 | Описание                         |
| --------------------------------------- | -------------------------------- |
| Сохранение соотношения сторон           | Пропорциональное масштабирование |
| Масштабирование по максимальной стороне | До 2500 пикселей                 |
| Сжатие JPEG                             | Качество 90%                     |

> **Пример:** Если загружено изображение 4000×3000, сервер масштабирует его до 2500×1875 (сохраняя пропорции 4:3) и сжимает до JPEG 90%.

### Видео

| Параметр           | Значение                         |
| ------------------ | -------------------------------- |
| Сжатие на клиенте  | Рекомендуется, но не обязательно |
| Отправка оригинала | Разрешена                        |
| Макс. размер       | 512 МБ                           |

> Клиент может отправить видео без сжатия. Рекомендуется применять сжатие на стороне клиента для экономии трафика и ускорения загрузки.

### Документы

| Параметр | Значение                 |
| -------- | ------------------------ |
| Сжатие   | Не применяется           |
| Отправка | Только оригинальный файл |

> Документы (PDF, DOCX, ZIP и др.) всегда отправляются в исходном виде без какого-либо сжатия или конвертации.

### Рекомендации по реализации на клиентах

1. **Предварительная проверка** — перед отправкой проверять размер и разрешение файла локально
2. **Предварительный просмотр** — показывать пользователю превью изображения/видео перед отправкой
3. **Прогресс загрузки** — отображать индикатор прогресса для больших файлов
4. **Обработка ошибок** — информировать пользователя при превышении лимитов

## Приложение B: Типы вложений в сообщениях

Система поддерживает 6 типов вложений, которые автоматически определяются сервером по сигнатуре файла (magic bytes).

### Общая структура вложения

Каждое вложение содержит следующие поля:

| Поле             | Описание                                    |
| ---------------- | ------------------------------------------- |
| `id`             | Идентификатор вложения                      |
| `type`           | Тип вложения (enum)                         |
| `file_id`        | Идентификатор файла в хранилище             |
| `preview_url`    | Ссылка на превью (для изображений)          |
| `preview_file_id`| Идентификатор файла превью                  |
| `attachment_size`| Размер файла в байтах                       |
| `file_name`      | Оригинальное имя файла                      |

---

### 1. Изображение (IMAGE)

**Proto-тип:** `MESSAGE_ATTACHMENT_TYPE_IMAGE = 1`

**Поддерживаемые форматы:**
- JPEG / JPG
- PNG
- BMP
- WebP

**Обработка на сервере:**
- Автоматическое определение типа по magic bytes
- Принудительное сжатие до 2500×2500 px (сохранение пропорций)
- JPEG качество: 90%
- Максимальный размер: 2 МБ (после сжатия)
- Генерация превью: 1024 px по длинной стороне

**Отображение в клиенте:**

| Элемент             | Рекомендация                                                    |
| ------------------- | --------------------------------------------------------------- |
| Превью в чате       | Отображать `preview_url` в сетке (до 4 изображений в ряд)       |
| Полный просмотр     | Открытие `file_url` в ImageViewerActivity / полноэкранном mode  |
| Placeholder         | Скелетон или размытый thumbnail во время загрузки               |
| Жесты               | Zoom, pan, swipe для перехода между изображениями               |

---

### 2. Видео (VIDEO)

**Proto-тип:** `MESSAGE_ATTACHMENT_TYPE_VIDEO = 2`

**Поддерживаемые форматы:**
- MP4 (ftyp atom)
- WebM (EBML header)
- AVI (RIFF....AVI)
- MOV / QuickTime

**Обработка на сервере:**
- Автоматическое определение типа по magic bytes
- Без сжатия (оригинал)
- Максимальный размер: 512 МБ
- Превью: не генерируется

**Отображение в клиенте:**

| Элемент             | Рекомендация                                                    |
| ------------------- | --------------------------------------------------------------- |
| Превью в чате       | Иконка видео ▶ с длительностью (если доступна метаданными)      |
| Воспроизведение     | ExoPlayer (Android), AVPlayer (iOS), MediaPlayer (WPF)          |
| Потоковое воспр.    | Рекомендуется progressive download или HLS при поддержке        |
| Контролы            | Play/Pause, seek bar, fullscreen toggle                         |

---

### 3. GIF-анимация (GIF)

**Proto-тип:** `MESSAGE_ATTACHMENT_TYPE_GIF = 3`

**Поддерживаемые форматы:**
- GIF (GIF8 signature)

**Обработка на сервере:**
- Автоматическое определение типа по magic bytes
- Без сжатия и конвертации (сохраняется анимация)
- Максимальный размер: 512 МБ
- Превью: не генерируется (используется оригинал)

**Отображение в клиенте:**

| Элемент             | Рекомендация                                                    |
| ------------------- | --------------------------------------------------------------- |
| Превью в чате       | Отображать анимированный GIF напрямую                           |
| Полный просмотр     | ImageViewerActivity (без отдельного экрана для GIF)             |
| Оптимизация         | Рассмотреть кеширование первого кадра для списков               |

---

### 4. Документ (DOCUMENT)

**Proto-тип:** `MESSAGE_ATTACHMENT_TYPE_DOCUMENT = 4`

**Поддерживаемые форматы:**
- Любые файлы, не попадающие под другие категории
- PDF, DOCX, XLSX, ZIP, APK, и т.д.

**Обработка на сервере:**
- Тип по умолчанию для нераспознанных файлов
- Без сжатия и конвертации
- Максимальный размер: 512 МБ
- Превью: не генерируется

**Отображение в клиенте:**

| Элемент             | Рекомендация                                                    |
| ------------------- | --------------------------------------------------------------- |
| Превью в чате       | Иконка файла + имя файла + размер                               |
| Действие            | Нажатие — скачивание во временное хранилище                     |
| Открытие            | Через системное приложение (Intent / ShareSheet / Process.Start)|
| Прогресс            | Отображать прогресс загрузки для файлов > 1 МБ                  |

**Рекомендуемые иконки по расширению:**

| Расширение          | Иконка                       |
| ------------------- | ---------------------------- |
| .pdf                | Иконка PDF документа         |
| .doc, .docx         | Иконка Word                  |
| .xls, .xlsx         | Иконка Excel                 |
| .zip, .rar, .7z     | Иконка архива                |
| .apk                | Иконка Android               |
| другие              | Универсальная иконка файла   |

---

### 5. Аудио (AUDIO)

**Proto-тип:** `MESSAGE_ATTACHMENT_TYPE_AUDIO = 5`

**Поддерживаемые форматы:**
- MP3 (MPEG Audio Layer 3, frame sync или ID3 tag)
- WAV (RIFF....WAVE)
- FLAC
- M4A / AAC (ftyp с M4A, M4B, isom, mp41, mp42 брендами)

**Обработка на сервере:**
- Автоматическое определение типа по magic bytes
- Без сжатия
- Максимальный размер: 512 МБ
- Превью: не генерируется

**Отображение в клиенте:**

| Элемент             | Рекомендация                                                    |
| ------------------- | --------------------------------------------------------------- |
| Превью в чате       | Иконка аудио 🎵 + имя файла + длительность                      |
| Воспроизведение     | MediaPlayer (Android), AVAudioPlayer (iOS), MediaPlayer (WPF)   |
| Инлайн-плеер        | Play/Pause кнопка, прогресс-бар, waveform (опционально)         |
| Фоновое воспр.      | Только одно аудио за раз (singleton pattern)                    |

---

### 6. Голосовое сообщение (VOICE)

**Proto-тип:** `MESSAGE_ATTACHMENT_TYPE_VOICE = 6`

**Поддерживаемые форматы:**
- OGG (OggS signature) — основной формат для голосовых сообщений

**Обработка на сервере:**
- Автоматическое определение типа по magic bytes (OGG signature)
- Без сжатия
- Максимальный размер: 512 МБ
- Превью: не генерируется

**Отображение в клиенте:**

| Элемент             | Рекомендация                                                    |
| ------------------- | --------------------------------------------------------------- |
| Превью в чате       | Waveform визуализация + длительность                            |
| Воспроизведение     | Инлайн-плеер с автоматическим воспроизведением                  |
| Скорость            | Опционально: переключение скорости (1x, 1.5x, 2x)               |
| Запись              | Клиент должен кодировать в OGG/Opus при отправке                |
| Отличие от AUDIO    | Компактный UI, без отображения имени файла, waveform обязателен |

### Рекомендации по реализации отображения вложений

#### Сетка изображений (Image Grid)

При нескольких изображениях в одном сообщении:

| Количество | Расположение                           |
| ---------- | -------------------------------------- |
| 1          | Полная ширина, ограничение по высоте   |
| 2          | 2 колонки, равная ширина               |
| 3          | 1 большое + 2 маленьких снизу          |
| 4+         | Сетка 2×2, остальное по tap            |

#### Общие принципы

1. **Кеширование** — использовать disk cache (FileCache) для загруженных файлов
2. **Ленивая загрузка** — загружать превью только для видимых элементов
3. **Прогресс** — отображать индикатор загрузки для файлов > 100 КБ
4. **Обработка ошибок** — информировать пользователя при неудачной загрузке
5. **Отмена** — возможность отменить загрузку/скачивание
