# BarkFluff 隐私政策

**生效日期：** 2026 年 1 月 24 日  
**最后更新：** 2026 年 7 月 29 日

> 本译文仅供参考。如有歧义，以俄文版本为准。

## 1. 谁对您的数据负责

BarkFluff 是由相互独立的服务器（“节点”）组成的联邦网络。每个节点由其管理员部署和运维；节点之间相互通信，以连接不同节点的用户。

您的个人数据的控制者是**创建您账户的那个节点的管理员**。他托管各项服务，拥有数据库、文件存储、备份和日志，决定保存期限，答复您的请求，并对遵守适用于他的法律负责。

BarkFluff 的开发者发布软件和协议规范。他们**不**托管他人的节点，**无法**访问这些节点的数据、密钥、流量和备份，**不能**在他人节点上提供、修改或删除数据，也**不是**您数据的控制者。

本文件描述软件在默认配置下的行为，适用于 **barkfluff.com** 节点。任何其他节点的管理员都会发布自己的版本，并有权修改配置或源代码——届时以其条款为准。如果您的账户不是在 barkfluff.com 上创建的，请联系您所在节点的管理员。

## 2. 节点管理员在技术上能看到什么

- 普通的单聊和群聊消息以明文形式存储在节点上。节点管理员对数据库、文件存储和日志拥有技术访问权限，**可以读取其内容**。
- 私密聊天在服务器上只保存密文；密钥在您的设备上由 passphrase 派生，不会传给节点。
- 秘密聊天仅由节点在设备之间转发，不作为历史记录保存。
- 如果您不愿意信任某个节点的管理员，请使用私密聊天或秘密聊天，或者自行部署节点。

## 3. 处理哪些数据

### 3.1 账户与个人资料

| 数据 | 用途 | 存储位置 |
| --- | --- | --- |
| 电子邮件 | 注册、登录、确认、找回访问权限、通知 | Users / Identity |
| 用户名 | 登录、搜索、公开个人资料页面、在聊天中显示 | Users |
| 密码哈希 | 密码校验；不存储明文密码 | Identity |
| 名字、姓氏、简介 | 用户资料与公开资料数据 | Users |
| 头像与资料封面 | 个人资料及公开页面的展示 | Files / Minio + Users 元数据 |
| 隐私与个性化设置 | 资料数据的展示、客户端外观、是否允许联邦聊天 | Users |

### 3.2 设备与会话

| 数据 | 用途 | 存储位置 |
| --- | --- | --- |
| Device ID | 绑定刷新令牌、活动会话列表、撤销会话 | Identity.RefreshTokens、Users.UserDevices |
| 设备名称 | 显示与重命名设备 | Users.UserDevices |
| 操作系统、应用名称 | 客户端兼容性与设备列表 | Users.UserDevices |
| Location | 在会话列表中显示设备 | Users.UserDevices |
| Firebase 令牌 | 通过 Firebase Cloud Messaging 推送通知 | Users.UserDevices |
| 刷新令牌 | 续期会话与从设备退出登录 | Identity.RefreshTokens |

IP 地址在 gRPC 服务元数据头中传递，用于处理当前请求。这些数据不会离开您的节点，也不会传给其他节点。

### 3.3 消息、聊天与文件

| 数据 | 用途 | 存储位置 |
| --- | --- | --- |
| 普通消息 | 单聊与群聊、同步、已读回执、编辑与删除 | Messages / PostgreSQL |
| 私密加密聊天 | 采用客户端加密的一对一聊天，仅限同一节点内 | Messages 保存密文与聊天元数据 |
| 秘密聊天 | 特定设备之间的一对一聊天，仅限同一节点内 | 节点转发 envelope 并临时缓冲 |
| 附件与预览 | 传输文件、图片、视频、文档、音频与头像 | Files / Minio + PostgreSQL 元数据 |
| 已读状态 | 显示已读消息 | Messages |

### 3.4 在线状态与更新

Onliner 保存并提供在线状态和最后活动时间。Updates 通过 gRPC streaming 向客户端推送实时事件。

### 3.5 网站与支持

WebServer 提供首页、公开个人资料页面、法律页面、安装脚本、客户端版本以及公开资料 REST API。网站支持表单中的消息保存在 WebServer 进程内存中，并在节点管理员配置了转发的情况下，通过 Telegram Bot API 转发给他。

在公开个人资料页面点击“在浏览器中发消息”时，WebServer 会创建短时 cookie `bf_open_chat`，以便 Web 客户端打开与所选用户的聊天。

## 4. 联邦数据交换

联邦默认关闭（`Federation:Enabled = false`），由节点管理员开启。开启后，当您与其他节点的用户通信时，部分数据会越过您所在节点的边界。

| 发往其他节点的内容 | 时机 | 方式 |
| --- | --- | --- |
| 标识符、用户名、姓名与资料头像 | 当其他节点的用户找到您或打开您的资料卡时 | 节点间的资料查询，遵循您的隐私设置 |
| 消息正文、编辑、删除、已读回执 | 与其他节点用户的一对一会话 | 带签名的事件，保证送达并支持重试 |
| 文件与附件 | 当对方打开文件时 | 应对方节点请求以流式提供；不会预先创建副本 |
| 在线状态与最后活动时间 | 联邦聊天处于活动状态期间 | 节点间的实时流；适用您的隐私设置 |
| “正在输入…” | 您输入消息时 | 一次性通知，不予保存 |

需要明确的要点：

- 联邦聊天仅限一对一单聊。不支持跨节点的群聊。
- **联邦消息没有端到端加密。** 其内容对您所在的节点和对方所在的节点均可见。私密聊天与秘密聊天仅在同一节点内可用。
- 接收数据的节点会成为其副本的**独立控制者**。您的节点和开发者都无法控制该节点保存这些数据的时长与方式。其模型与电子邮件相同。
- 在您的节点上删除消息或账户**不会删除**已送达其他节点的副本。目前不存在跨联邦的删除自动传播机制。
- 您可以在隐私设置中拒绝接收联邦单聊——此后从其他节点发起的建聊请求将被拒绝。
- 您所在节点的管理员可以整体封禁某个节点，与其的数据交换即告终止。

**技术保证及其边界。** 节点间事件使用 Ed25519 签名，连接使用 TLS 并校验服务器密钥指纹，请求在有限时间窗口内签名。这能证明数据**来自哪个节点**且在传输中未被篡改，但对该节点管理员如何处置所收到的副本不提供任何保证。

## 5. 数据的用途

- 注册、登录、两步验证、找回密码与会话管理；
- 个人资料、用户搜索、公开页面与隐私设置；
- 投递消息、文件、已读回执、实时更新与推送通知；
- 在联邦开启时与其他节点的用户交换消息；
- 通过 `Users.ExportData` 导出用户数据；
- 通过节点管理员配置的渠道提供用户支持；
- 记录错误、指标与安全事件。

## 6. 数据保护

### 6.1 数据传输

- 客户端与微服务在外部边界使用 gRPC/HTTP/2 与 HTTPS/TLS。
- gRPC 请求的鉴权使用 XAuth 元数据：`x-auth-token`、`x-device-id`、`x-device-name`、`x-ip`、`x-os`、`x-app-name`、`x-app-version`。
- 内部异步事件通过 RabbitMQ / MassTransit 传递。
- 节点之间的流量走单独的安全通道，详见《加密》。

### 6.2 密码、令牌与两步验证

- 密码以哈希形式存储。
- Access token 是位于 `x-auth-token` 头中的 JWT；有效期由您所在节点的 Identity 配置决定。
- 刷新令牌绑定到 Device ID，保存在 Identity 中。
- 两步验证支持 TOTP 验证器与邮件验证码。

### 6.3 加密聊天

- **私密聊天：** 节点保存 `EncryptedMessage` 密文、nonce 与 AAD；密钥在客户端由 passphrase 和聊天盐值派生。
- **秘密聊天：** 节点处理与设备绑定的不透明 envelope，将其转发给接收方并以 24 小时 TTL 缓冲。
- **普通聊天：** 消息保存在您所在节点的 Messages 服务中，服务端逻辑与节点管理员均可访问。

## 7. 向第三方提供

不出售个人数据。仅为运行节点管理员启用的功能，才会将数据提供给外部服务商：

- **联邦中的其他节点：** 见第 4 节。
- **SMTP：** 邮件通知、确认码、找回访问权限。
- **Firebase Cloud Messaging：** 向持有 Firebase 令牌的设备推送通知。
- **Telegram Bot API：** 处理网站支持聊天中的消息。
- **托管与基础设施：** 承载服务、数据库、文件存储、RabbitMQ、Redis 与 Seq。

具体使用哪些服务商由节点管理员决定：他可以关闭推送、改用其他 SMTP 服务，或者完全不使用 Telegram。

## 8. 用户权利

有关您数据的请求请发给您所在节点的管理员——只有他能够执行。

- **访问与导出：** 导出会返回 JSON 文件 `profile.json`、`messages.json` 与 `files.json`。
- **更正：** 资料、简介、头像、封面、隐私、设备与密码可通过客户端中可用的功能修改。
- **删除：** 见《账户删除政策》。
- **撤销会话：** 可通过设备管理功能结束活动会话。
- **限制联邦：** 可在隐私设置中拒绝接收联邦单聊。

## 9. 删除消息与数据

- 普通消息支持通过 Messages API 删除。
- 私密加密消息在删除时被标记为已删除，密文被清除。
- 秘密消息在确认送达或 TTL 到期后从临时缓冲中删除。
- 删除仅在您所在节点内生效。已送达其他节点的副本只能由该节点的管理员删除。
- 若需删除账户以及客户端功能未覆盖的数据，请联系节点管理员。

## 10. Cookie 与本地存储

- 原生客户端使用本地存储保存令牌、设置与缓存。
- Windows 客户端保存 `GlobalParam.json`，并可用 PIN 码保护。
- macOS 客户端使用 Keychain 保存令牌。
- WebServer 仅在从公开个人资料页面跳转到 Web 客户端时使用 cookie `bf_open_chat`。

## 11. 儿童

BarkFluff 不面向 13 岁以下用户。节点管理员有权设定更高的年龄门槛。如果您认为有 13 岁以下儿童创建了账户，请通知相应节点的管理员。

## 12. 政策变更

本政策变更时会更新“最后更新”日期。重大变更可能通过应用或电子邮件告知。节点管理员自行发布其版本的变更。
