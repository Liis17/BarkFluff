# 09 — Проблемы, риски и открытые вопросы

Реестр всего, что может выстрелить. Статусы: **решено** (решение зафиксировано в доках), **смягчено** (риск принят с контрмерами), **открыто** (требует решения до/во время реализации соответствующей фазы).

## Идентичность и адресация

| # | Проблема | Статус | Решение / что делать |
|---|----------|--------|----------------------|
| 1 | Коллизии `long UserId` между нодами | решено | UUID-слой; long не покидает ноду ([01](01-addressing-identity.md)) |
| 2 | Коллизии `Message.Id` (bigserial) | решено | `FederatedId` (uuid) для fed-сообщений ([05](05-chat-replication.md)) |
| 3 | Смена username ломает FID | смягчено | UUID — стабильный якорь; события профиля + TTL-рефреш кеша |
| 4 | Вредоносная нода заявляет чужой UUID | смягчено | UUID пиннится к ServerName при знакомстве; смена — отказ. Миграция аккаунта между нодами — **вне скоупа**, отдельная будущая проработка |
| 5 | Спуфинг авторства | решено | Нода говорит только за свой домен; проверка `sender.server == origin` подписи |

## Доверие и криптография

| # | Проблема | Статус | Решение / что делать |
|---|----------|--------|----------------------|
| 6 | CA может отозвать серт ноды | решено | Self-signed допустим; подлинность — Ed25519-подписи, транспорт — SPKI-пиннинг ([02](02-trust-and-certs.md)) |
| 7 | MITM при первом контакте (TOFU) | смягчено | Кросс-проверка Navigator + ручные пиры + лог смены ключей. Остаточный риск принят |
| 8 | Компрометация signing-ключа | смягчено | Ротация, отзыв в discovery-документе; окно timestamp 5 мин ограничивает replay |
| 9 | Clock skew между нодами | смягчено | NTP-требование; `Ping` с временем; код ошибки ClockSkew; tie-break в LWW |
| 10 | Ed25519 в .NET 10: доступность API | **открыто** | Исследовать `System.Security.Cryptography` vs NSec/BouncyCastle — задача Фазы 1 |
| 11 | Replay-атаки | смягчено | timestamp-окно + (для мутаций) идемпотентность по event_id; при необходимости nonce-кеш |

## Приватность и злоупотребления

| # | Проблема | Статус | Решение / что делать |
|---|----------|--------|----------------------|
| 22 | Спам с чужих нод | решено (MVP-уровень) | Default open + user-настройка `AllowFederatedDm` + серверный блоклист нод. Пользовательская блокировка конкретных отправителей — будущая фаза (сервиса блокировок нет и для локальных) |
| 23 | GDPR: наши данные лежат копиями на чужих нодах | **открыто** | Best-effort `UserDeactivated`/delete-запросы; юридически честный ответ — задокументировать для пользователей, что федеративная переписка покидает контроль ноды (как email). Проработать в отдельной задаче |
| 24 | Экспорт данных (GDPR) должен включать fed-чаты | решено | Локальная копия чата попадает в существующий ExportData |
| 25 | DoS публичного эндпоинта | смягчено | nginx rate limit + прикладной per-origin + лимиты батчей |
| 26 | Злая нода шлёт мусорные события валидной подписью | смягчено | Лимиты контента = локальным; блоклист; метрики аномалий. Репутация/автомодерация — вне скоупа |
| 27 | Privacy-настройки применяются чужой нодой (мы ей доверяем фильтрацию нашего presence/профилей — нет, наоборот: **origin фильтрует сам**) | решено | Инвариант: данные фильтрует владелец до отправки ([07](07-presence-typing.md)) |

## Отложенные фичи (следующие задачи по проработке — по решению владельца)

Каждая — отдельный планировочный документ, когда дойдёт очередь:

| Фича | Ключевые проблемы, уже видимые сейчас |
|------|--------------------------------------|
| **Федеративные группы** | Консистентность членства между N нод; права (UsersCanKick) с remote-модераторами; системные сообщения; выбор «домашней» ноды группы vs репликация; наплыв нод-участников в outbox |
| **Федеративные приватные чаты (passphrase E2E)** | Обмен KdfSalt/PassphraseVerifier между нодами; хранение шифротекста на двух нодах (безопасно — сервер и так не видит plaintext); инвайт-флоу через федерацию |
| **Федеративные секретные чаты (Signal/X3DH)** | Кросс-нодовый `FetchPrekeyBundle` (атомарный расход one-time prekey на чужой ноде!); device-scope доставка на устройства remote-пользователя; Redis-буфер 24ч на чьей стороне |
| **Федеративные боты** | Адресация `@bot:server`; Bot API токены не пересекают ноды — вызовы через федерацию от имени ноды бота |
| **Кросс-нодовые звонки** | LiveKit SFU принадлежит ноде — чей SFU используется; выдача LiveKit-токенов пользователям чужой ноды; TURN/ICE через границы |
| **Пользовательская блокировка отправителей** | Нужен и для локальных; для fed — блок по UUID |
| **Миграция аккаунта между нодами** | Перенос UUID с доказательством владения; редиректы FID |
