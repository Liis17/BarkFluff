# Этап 2.8 — Пуши: имя remote-отправителя

## Цель

Отложенный push на ноде получателя показывает имя (или FID) remote-отправителя вместо пустоты/ID. Механика доставки пушей не меняется — копия чата локальна, `NewMessageEvent` штатный.

## Контекст

- [../05-chat-replication.md](../05-chat-replication.md), «Пуши и realtime»; [../08-service-migration.md](../08-service-migration.md), секция CloudMessaging.
- Поля `SenderDisplayName`/`SenderFid` в расширенном `NewMessageEvent` заведены в 2.2, заполняются Messages с 2.3.
- Требуется выполненный 2.3.

## Изменение 1 — Messages: заполнение имени при импорте

`ImportFederatedMessage` (2.3) публикует `NewMessageEvent` — проверь, что `SenderDisplayName` (из `RemoteUsers` через `Users.GetUsersByUuid`, кеш) и `SenderFid` (`@username:servername`) заполняются. Имени нет (профиль скрыт/не синхронизирован) → `SenderDisplayName` пустой, `SenderFid` обязателен.

## Изменение 2 — CloudMessaging

Найди, откуда формируется заголовок пуша (имя отправителя) в пути обработки `NewMessageEvent`. Для события с `SenderUuid` (remote): имя = `SenderDisplayName`, fallback — `SenderFid`. Существующий путь по `SenderId` (локальные) не трогать. Mute-фильтр работает без изменений (ChatId общий).

Проверь также путь **счётчиков/текста превью** пуша: если где-то резолвится отправитель по `SenderId` через Users — ветка для `SenderId = NULL` не должна падать.

## Чего НЕ делать

- Аватар в пуше с origin-ноды — Фаза 3.
- Клиентский рендер FID в системном уведомлении — на стороне клиентов и так отображается строка из пуша; клиентские правки — Фаза 5.
- Локализация формата FID — нет.

## Критерии готовности

1. Стенд, критерий роадмапа: клиент пользователя node2 оффлайн (стрим Updates закрыт) → пользователь node1 шлёт сообщение → push через CloudMessaging node2 содержит имя отправителя; при скрытом профиле — FID.
   Если на стенде нет реального FCM-канала — критерий проверяется до точки формирования пуша: лог/юнит-тест хендлера CloudMessaging с расширенным событием (имя и fallback-FID), плюс существующий механизм доставки не менялся.
2. Юнит-тест: событие с `SenderUuid` без имени → заголовок = FID; локальное событие → поведение прежнее.
3. Obsidian: `Backend/CloudMessaging.md` дополнен.
4. Коммит: `feat(rearch-phase2): 2.8 — имя remote-отправителя в пушах`.
