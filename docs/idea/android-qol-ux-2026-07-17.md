# Android-клиент: QoL/UX идеи (срез dev, 2026-07-17)

Дата анализа: 2026-07-17. Ветка: `dev`.

## Контекст

Проверено по `Obsidian/ClaudeVault/Клиенты/Android.md` и коду
`Android/Barkfluff.Client.Android/app/src/main/java/com/barkfluff/client/`.
Есть более ранний обзор [`docs/android-v1-qol-and-features.md`](../android-v1-qol-and-features.md)
(2026-07-10, 20 идей) — часть его пунктов к текущему моменту уже реализована
(offline-first кеш чатов, per-chat mute, закрепление **сообщений**). Ниже —
точечный список того, что подтверждённо отсутствует в коде на 2026-07-17, без
повторения уже сделанного.

Обозначения: **Android** — можно реализовать преимущественно на клиенте;
**API** — понадобится поддержка бэкенда и proto; **оба** — работа в обеих частях.

## Подтверждённо отсутствует

1. **Typing indicator** («печатает…») — нет `isTyping`/`typing` ни в proto,
   ни в `RealtimeService`. **Оба**
2. **Реакции на сообщения** (emoji) — отсутствуют полностью, ни в proto, ни в
   клиенте. **Оба**
3. **Поиск по тексту сообщений** — ни внутри чата, ни глобально;
   `SearchActivity` ищет только пользователей через `UsersApi.SearchUsers`.
   **Оба**
4. **Мульти-select сообщений** (выделить несколько → массово удалить/
   переслать) — меню действий (`popup_message_actions.xml`) работает только с
   одним сообщением за раз. **Android**
5. **Свайп-действия в списке чатов** (свайп чата → mute/удалить/архив) —
   `ItemTouchHelper` есть только для reply-свайпа внутри открытого чата
   (`ReplySwipeCallback`), в `ChatsFragment.chatRecyclerView` его нет.
   Паттерн уже отработан, можно переиспользовать. **Android**
6. **Закрепление чата вверху списка / архивирование чатов** — не путать с уже
   реализованным закреплением **сообщений** (`actionPin` в `ChatActivity`);
   на уровне списка чатов такого нет. **Оба**
7. **@упоминания в группах** — нет автокомплита/подсветки/приоритетного пуша
   по `@username`. **Оба**
8. **Черновики сообщений** — текст/reply/вложения не сохраняются при выходе
   из чата. **Android**
9. **Отложенная отправка** сообщений — нет ни в proto, ни в клиенте. **Оба**
10. **Превью ссылок** (OpenGraph-карточка для URL в тексте сообщения) — есть
    только превью вложенных файлов, для текстовых URL превью нет. **Оба**

Read receipts на уровне участников (`read_by` в `shared.proto`,
`MessageReadEvent` в `updates_api.proto`, обработка в `RealtimeService`) уже
реализованы на бэкенде и в клиенте — просто нет отдельного UI со списком
аватаров «кто прочитал» в групповом чате, если такая визуализация нужна.

## Рекомендуемый порядок (impact/effort)

1. **Закрепление чата вверху списка** — небольшая фича, в основном клиент +
   одно поле в API, заметный ежедневный эффект.
2. **Свайп-действия в списке чатов** (mute/delete) — паттерн уже есть
   (`ReplySwipeCallback`), переиспользуется почти без нового кода.
3. **Черновики** — полностью локально, без бэкенда (`GlobalParam`/
   SharedPreferences per chatId).
4. **Поиск по сообщениям в открытом чате** — как первый шаг можно сделать
   client-side по уже загруженной/закешированной истории, без нового
   gRPC-метода; полноценный поиск по всей истории потребует API.
5. **Typing indicator** и **реакции** — самые дорогие по объёму работы (новый
   realtime-стрим + изменения в proto на бэкенде), но и наиболее заметные
   пользователю.
