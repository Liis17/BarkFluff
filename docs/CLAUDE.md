# Анализ проекта BarkFluff

## Обзор проекта

Это крупный, распределенный проект .NET с микросервисной архитектурой. Система представляет собой платформу для общения в реальном времени с такими функциями, как обмен сообщениями, управление пользователями, обмен файлами и уведомления. Она также включает в себя функции на базе искусственного интеллекта, такие как перевод текста и модерация контента.

**Основные технологии:**

*   **.NET (C#):** Основная технология для всех бэкенд-сервисов и клиента WPF.
*   **gRPC:** Используется для эффективного взаимодействия между микросервисами.
*   **Docker:** Для контейнеризации и оркестрации сервисов.
*   **WPF:** Фреймворк для настольного клиентского приложения.
*   **RabbitMQ:** Для асинхронного обмена сообщениями и событийно-ориентированного взаимодействия.
*   **Redis:** Для кеширования и управления сессиями.
*   **PostgreSQL:** Основная база данных для приложения.
*   **Minio:** Для хранения пользовательского контента, такого как файлы и аватары.

**Архитектура:**

Бэкенд состоит из нескольких микросервисов, каждый из которых выполняет определенную функцию. Большинство сервисов следуют схожей структуре, включающей:

*   **Domain:** Содержит основную бизнес-логику и сущности.
*   **Features:** Реализует функции приложения, вероятно, с использованием CQRS-подобного паттерна.
*   **Host:** Настраивает веб-хост и сервисы.
*   **Infrastructure:** Содержит реализации интерфейсов, определенных в домене, таких как репозитории или клиенты внешних сервисов.
*   **Persistence:** Обрабатывает доступ к данным и взаимодействие с базой данных.

**Описание микросервисов:**

*   **[Identity](./Backend/BarkFluff.Identity/GEMINI.md):** Управляет аутентификацией и авторизацией пользователей. Реализует функции регистрации, входа в систему и генерации токенов.
*   **[Users](./Backend/BarkFluff.Users/GEMINI.md):** Управляет профилями пользователей и их отношениями. Реализует функции получения и обновления профилей, а также управления отношениями между пользователями.
*   **[Files](./Backend/BarkFluff.Files/GEMINI.md):** Обрабатывает хранение и извлечение файлов. Реализует функции загрузки, скачивания и удаления файлов, взаимодействуя с Minio.
*   **[Messages](./Backend/BarkFluff.Messages/GEMINI.md):** Управляет обменом сообщениями в реальном времени между пользователями. Реализует функции отправки, получения и хранения сообщений, используя RabbitMQ для асинхронной доставки.
*   **[Notification](./Backend/BarkFluff.Notification/GEMINI.md):** Отправляет уведомления пользователям. Использует RabbitMQ для получения сообщений о событиях и отправляет уведомления по различным каналам (например, push-уведомления).
*   **[Beacon](./Backend/BarkFluff.Beacon/GEMINI.md):** Центральный сервис для gRPC-коммуникации. Выступает в качестве точки входа для gRPC-запросов от других микросервисов.
*   **[Configuration](./Backend/BarkFluff.Configuration/GEMINI.md):** Обеспечивает централизованную конфигурацию для всех сервисов. Хранит и извлекает настройки из постоянного хранилища.
*   **[FastAuth](./Backend/BarkFluff.FastAuth/GEMINI.md):** Сервис для быстрой аутентификации. Предоставляет легковесный механизм аутентификации.
*   **[Navigator](./Backend/BarkFluff.Navigator/GEMINI.md):** Сервис для навигации. Управляет и предоставляет данные о навигации в приложении.
*   **[Updates](./Backend/BarkFluff.Updates/GEMINI.md):** Сервис для взаимодействия в реальном времени и потоковой передачи данных. Использует gRPC streaming для подписки на различные обновления (например, новые сообщения).

Проект `BarkFluff.Client.WPF` представляет собой настольное приложение, которое предоставляет пользовательский интерфейс для платформы.

**Взаимодействие между микросервисами:**

*   **Обнаружение сервисов:** Сервис `Configuration` действует как реестр сервисов. Каждый микросервис при запуске запрашивает у сервиса `Configuration` адреса других сервисов, с которыми ему необходимо взаимодействовать.
*   **Асинхронное взаимодействие:** RabbitMQ используется для асинхронного взаимодействия между сервисами. Например, сервис `Messages` потребляет события от сервиса `Users` (например, когда пользователь меняет свое имя или аватар) для обновления собственных данных. Сервис `Updates` потребляет события от сервиса `Messages` для отправки обновлений клиентам в реальном времени.
*   **Прямое взаимодействие:** Некоторые сервисы также взаимодействуют друг с другом напрямую через gRPC. Например, сервис `Users` взаимодействует с сервисом `Files` для получения аватаров пользователей, а сервис `Messages` взаимодействует с сервисами `Users` и `Files`.

**Общие proto-файлы:**

Все `.proto`-файлы, определяющие gRPC-сервисы и сообщения, находятся в каталоге `Shared/BarkFluff.Proto`.

### Общие библиотеки (Shared)

В папке `Shared` находятся общие библиотеки, которые используются всеми микросервисами в проекте. Это обеспечивает переиспользование кода и согласованность между сервисами.

*   **`BarkFluff.Proto`:** Этот проект содержит все `.proto`-файлы, которые определяют gRPC-сервисы и сообщения для всей системы. Это единый источник правды для контрактов API между микросервисами.
*   **`BarkFluff.Shared.Auth`:** Эта библиотека содержит перехватчики клиента gRPC для аутентификации. Эти перехватчики используются для добавления информации об аутентификации (например, JWT) в исходящие запросы gRPC. Она включает перехватчики для обработки JWT, идентификаторов устройств, IP-адресов и операционных систем.
*   **`BarkFluff.Shared.Identity`:** Эта библиотека содержит общие классы и перечисления, связанные с идентификацией пользователя. Сюда входят такие вещи, как `IdentityClaims`, `ServiceId` и `TokenType`. Это гарантирует, что одни и те же константы и перечисления, связанные с идентификацией, используются во всех микросервисах.
*   **`BarkFluff.Shared.SecurityUtilities`:** Эта библиотека, вероятно, содержит вспомогательные методы для задач, связанных с безопасностью, таких как хеширование, шифрование или другие операции, связанные с безопасностью.

## Сборка и запуск

### Бэкенд

Весь бэкенд можно запустить с помощью Docker Compose.

**Предварительные требования:**

*   Docker Desktop
*   Файл `.env` с необходимыми переменными окружения (см. `.env.example` в качестве шаблона).

**Чтобы запустить бэкенд:**

```bash
docker-compose -f Backend/docker-compose-dev.yml up -d
```

Это запустит все бэкенд-сервисы, а также необходимую инфраструктуру (PostgreSQL, RabbitMQ, Redis и Minio).

### Клиент

Клиент WPF можно запустить из Visual Studio, открыв файл `BarkFluff.sln` и установив `BarkFluff.Client.WPF` в качестве запускаемого проекта.

## Соглашения о разработке

*   **Стиль кода:** В проекте используется файл `.editorconfig` для обеспечения единого стиля кода.
*   **Модульность:** Проект является высокомодульным, с множеством общих проектов для общей функциональности.
*   **gRPC:** Все взаимодействие между сервисами осуществляется через gRPC. Файлы `.proto` для сервисов находятся в каталоге `Shared/BarkFluff.Proto`.
*   **CI/CD:** Проект использует GitHub Actions для непрерывной интеграции и развертывания. Файлы рабочих процессов находятся в каталоге `.github/workflows`.
