# BarkFluff.ClientV2.WPF — правила разработки

## Слои

- `Views` содержат только XAML и `InitializeComponent`; обработчики событий и бизнес-логика в code-behind запрещены.
- `ViewModels` содержат состояние экрана и команды. Для observable-свойств и команд используется `CommunityToolkit.Mvvm`.
- `Services` инкапсулируют навигацию, сетевое взаимодействие и состояние текущей сессии. ViewModel не вызывает `WebApi` напрямую.
- `Infrastructure` содержит технические реализации: SQLite и локализацию.
- `Models` — простые модели экрана и результаты операций, без UI-зависимостей.

## UI и локализация

- WPF UI — базовая библиотека контролов и тем.
- Общие стили контролов размещаются только в `Resources/Styles/Controls.xaml`.
- Все пользовательские строки находятся в `Resources/Localization/Strings.ru.xaml` и `Strings.en.xaml`; набор ключей в словарях должен совпадать.
- В XAML для локализованных строк использовать только `DynamicResource`.

## Данные и безопасность

- Локальная база: `data/barkfluff.db` рядом с исполняемым файлом.
- Доступ к SQLite идёт только через `IApplicationDataStore`; SQL-запросы параметризованы.
- Новые таблицы добавляются миграционно и только по фактической потребности. Токены, когда появится авторизация, хранятся через DPAPI, не в открытом виде.

## Сеть и тесты

- Подключение к ноде проходит через `INodeConnectionService`; `NodeConnectionMapper` преобразует `GetServerInfoResponse` в параметры клиентской сессии.
- Логика без UI покрывается xUnit-тестами: адреса нод, mapper, SQLite и ViewModel-сценарии.
- Перед изменением внешних библиотек сверяться с их актуальной документацией через Context7.
