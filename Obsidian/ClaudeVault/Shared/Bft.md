# Shared BFT

Parent: [[Index]]. `Shared/BarkFluff.Bft/` is the .NET 10 library for BFTv1 framing, cryptographic handshakes, multiplexed tunnels, client connection strings, and the Relay preamble. The backend Exit/Relay host consumes it from `Backend/BarkFluff.BftProxy/`.

## Public entry points

- `BftConnectionString` and `BftConnectionSettings` parse/format the `bft://` client link. `Parse` accepts both the classic form and the encoded form `bft://<base64url(body)>`; `Format` stays the canonical classic form, `FormatEncoded` produces the encoded link handed to users. Android mirrors this in `Android/core/.../bft/BftConnectionString.kt` (`parse`, `format`, `formatEncoded`).
- `BftClientHandshake` / `BftServerHandshake`, their option/result records, `BftNoiseSession`, and `BftClientTunnel` / `BftServerTunnel` establish an authenticated encrypted tunnel.
- `BftTunnelStream` exposes one multiplexed tunnel stream as a `Stream`; `BftFrameCodec`, frame enums/records, and `BftObfuscatedRecords` encode transport records.
- `BftRelayPreamble` and `BftRelayPreambleInfo` authenticate the client address and Relay ID between Relay and Exit.
- `BftCrypto`, `BftObfuscationKeys`, `BftSaltReplayCache`, `IBftRandomSource`, and protocol/stream exceptions provide the crypto, replay protection, injection seam, and failure surface.

The sole wire-format specification is `Docs/BFTv1.md`. Shared protocol vectors are stored in `Docs/bft/bftv1-vectors.json`, generated by `Docs/bft/generate_vectors.py`, and copied to the output of `Tests/BarkFluff.Bft.Tests/BarkFluff.Bft.Tests.csproj`. CI checks out the repository root, so the project-relative vector file is present during restore/build/test.

`Tests/BarkFluff.Bft.Tests/` exercises the public primitives and shared vectors. `Tests/BarkFluff.BftProxy.Tests/` covers the real loopback integration with the backend hosts; see [[Testing]] and [[Backend/BftProxy]].
