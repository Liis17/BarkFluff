# Тестирование бэкенда — состояние и паттерны

Состояние на 2026-06 (после аудита + 4 фаз исправлений). Актуальность числовых показателей проверять по факту — раздел описывает паттерны и известные ограничения, которые не меняются от коммита к коммиту.

## Тестовые проекты (`Tests/`)

8 «доменных» проектов (Files, Identity, Messages, Onliner, Users, CloudMessaging, FastAuth, + Navigator) плюс 3 добавленных позже инфраструктурных: `BarkFluff.GrpcServer.Tests` (TokenRevocationCache), `BarkFluff.Updates.Tests` (PendingPushTracker, подписочные менеджеры), `BarkFluff.Navigator.Tests` (RegisterServer-валидация). [[Backend/Federation]] покрыт отдельно, см. раздел «Тесты» в его файле.

Остаток `[Fact(Skip=...)]` сведён с 68 к 2 — оба требуют реального PostgreSQL (PG-специфичный raw SQL: `MarkAsRead` PG-массивы в Messages, `FetchPrekeyBundle` в Users). Это единственная категория, не лечащаяся ни SQLite, ни моками — нужен Testcontainers + PostgreSQL, трек не начат.

## Провайдер БД в тестах: почему SQLite, а не InMemory

Продакшн everywhere на `UseNpgsql`; провайдер выбирается в `Program.cs`, тесты конфигурируют контекст сами в `TestHelper.cs`. EF `UseInMemoryDatabase` не умеет raw SQL / `ExecuteDelete` / некоторые `GroupBy` — отсюда «фантомное покрытие» через Skip. [[Backend/Files]] переведён на `SqliteConnection("DataSource=:memory:")` + `UseSqlite` + `EnsureCreated` — закрыл все GroupBy/ExecuteDelete-скипы в этом сервисе. Раскатывать SQLite на Messages/Users смысла нет: их оставшиеся скипы — PG-специфичный raw SQL, который SQLite не исполнит вообще (не вопрос диалекта, а отсутствующих операторов).

## Размокивание Redis без изменения тестов

Приём для Messages (`PrivateChatInviteStore`, `SecretMessageBuffer`, `EncryptedMessageQueueSender`, `SecretMessageQueueSender`): тесты уже были написаны под `Mock<КонкретныйКласс>` — они не собирались только потому что публичные методы этих продакшн-классов не были `virtual` (Moq не может перехватить invocation на реальном Redis без этого). Сделать методы `virtual` в проде — минимальное изменение, тесты трогать не пришлось.

## GDPR-экспорт: реальный баг, найденный при снятии Skip

3 теста Users/ExportData были размечены Skip с неверной причиной («Moq cannot intercept» — на деле gRPC-методы виртуальны, перехватывались нормально). Реальная причина падений — NRE в `ExportDataCommandHandler`: `.ToString()` на незаданных proto-`Timestamp` (`SentAt`/`CreatedAt`/`UploadedAt`). `UploadFile.UploadedAt` — `DateTime?`, в проде бывает `null` (файл создан, но не догружен) → GDPR-экспорт реально падал бы. Фикс — null-guard `?.ToString()` в хендлере. Урок: Skip-тест с неверным комментарием прячет реальный баг — при снятии Skip сначала проверять, действительно ли причина в тесте, а не в проде.
