# Клиентский UI/UX ориентир

Parent: [[Index]]

Источник продуктовых сценариев — `Docs/dd.md`, а не файл в корне репозитория. Документ описывает желаемый платформонезависимый опыт; его старые API-примеры и матрица готовности не являются текущими контрактами. При реализации экрана сопоставляй сценарий с актуальным клиентом, [[Backend/Identity]], [[Backend/Files]] и [[Shared/Proto]].

## Основные сценарии

| Экран | Продуктовый ориентир |
|-------|---------------------|
| Welcome | Один раз при первом запуске: логотип, слоган, объяснение приватности/нод и переход к серверу |
| Защищённое хранение | Инициализировать до первого сохранения чувствительных данных; механизм и участие пользователя зависят от платформы |
| Select Server | Каталог Navigator или ручной Beacon endpoint, название/описание/handle/локация; запоминание ноды и индикатор доступности |
| Login | Username/email, пароль, переходы к восстановлению/регистрации/выбору ноды; подтверждение по действующему challenge API |
| FastAuth | QR-сценарий десктопа и подтверждение авторизованным мобильным устройством; фактическая поддержка — в клиентских заметках |
| Password Reset | Идентификация → подтверждение → новый пароль → успех; ошибки/cooldown/progress, без преждевременного сохранения токенов |
| Registration | Личные данные, username, email/подтверждение, пароль; фото/bio/2FA необязательны, затем завершение |
| Messenger | Список чатов и выбранный чат; адаптивное представление зависит от доступной ширины |

Разбиение регистрации на девять экранов — UI-ориентир, а не требование к числу серверных операций. Reset/смена пароля должны следовать текущим Identity RPC и security-proof ограничениям; старую цепочку удаления password hash из design-документа не копировать как действующую архитектуру.

## Вложения и медиа

Типы IMAGE/VIDEO/GIF/DOCUMENT/AUDIO/VOICE, определение MIME/типа, лимиты upload, compression и preview сверяй с [[Backend/Files]], [[Shared/Proto]] и клиентским transport. Числовые enum, фиксированные 2/512 МБ и JPEG-параметры из старого обзора не являются универсальным контрактом всех клиентов.

Продуктовый ориентир сетки: одно фото — крупное, два — две колонки, три — крупное и два меньших, четыре и больше — компактная сетка с раскрытием. Очередь вложений, caption, ошибки и отмену описывай в платформенной реализации. Расширение drag/drop — [[Ideas/20-DragDropMultiUpload]].

## Пароли и secure storage

Чеклист и индикатор силы помогают пользователю, но не задают серверную валидацию. Источник требований — [[Backend/Identity]]; оценка силы — [[Shared/SecurityUtilities]]. Не хранить отдельные расходящиеся минимумы для reset и смены пароля в общей памяти.

Механизмы хранения и блокировки проверяются по клиенту: Android encrypted preferences/SQLCipher, Apple Keychain, Windows DPAPI/локальные настройки, Linux собственный storage. Нельзя объявлять желаемое системное хранилище реализованным без источника.
