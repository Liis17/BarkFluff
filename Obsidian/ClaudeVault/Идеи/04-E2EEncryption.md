# 🔐 End-to-End шифрование чатов (E2EE)

> Категория: Безопасность
> Приоритет: 🔴 Высокий
> Сложность: ⭐⭐⭐⭐⭐

---

## Описание

Реализовать **настоящее E2E шифрование** для личных чатов по протоколу **Signal Protocol** (Double Ratchet + X3DH). Сервер хранит только зашифрованные блобы — даже администратор платформы не может прочитать сообщения.

---

## Ключевые возможности

- E2EE для 1-on-1 чатов (toggle в настройках чата)
- «Секретные чаты» — отдельный тип чата с E2EE по умолчанию
- Верификация устройств собеседника через «Safety Number» (отпечаток ключей)
- Уведомление при смене ключей собеседника
- E2EE + исчезающие сообщения (синергия с [[02-EphemeralMessages]])
- Вложения тоже шифруются на стороне клиента

---

## Протокол

```
X3DH (Extended Triple Diffie-Hellman) — начальное согласование ключей
Double Ratchet Algorithm — ротация ключей на каждое сообщение
```

**Ключи:**
- Identity Key (IK) — постоянный, хранится на устройстве
- Signed PreKey (SPK) — ротируется раз в неделю
- One-Time PreKeys (OPK) — пачка одноразовых ключей
- Session Key — уникален для каждого сообщения

---

## Архитектура

- Новый микросервис `BarkFluff.KeyStore` (порт 7035) — хранит публичные ключи (только публичные!)
- Клиент генерирует ключи локально и публикует публичные части в KeyStore
- Приватные ключи **никогда не покидают устройство**
- Сообщения в Messages сервисе хранятся как `encrypted_blob BYTEA`
- Новое поле в proto: `is_encrypted`, `encrypted_payload`

## Клиентская реализация

- Android: `libsignal-android` (Signal Foundation)
- iOS/macOS: `libsignal-swift`
- .NET (WPF): `libsignal-net` или C биндинги через P/Invoke
- Ключи хранятся в защищённом хранилище (Keychain / EncryptedSharedPreferences / DPAPI)

## UX

- Замочек 🔒 в шапке E2EE чата

- Предупреждение «Ключи изменились» если собеседник переустановил приложение
