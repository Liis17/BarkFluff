📋 Требования

Для развертывания BarkFluff вам потребуется:

  • Docker и Docker Compose (рекомендуется версия 2.0+)
  • Минимум 4 ГБ ОЗУ (рекомендуется 8 ГБ для комфортной работы)
  • 2 ядра CPU (рекомендуется 4 ядра)
  • 10 ГБ дискового пространства (зависит от количества пользователей и хранимых файлов)
  • Доменное имя (для HTTPS и доступа извне)
  • SSL-сертификат (можно получить бесплатно через Let's Encrypt)
Важно

BarkFluff находится в активной разработке. Некоторые функции могут быть нестабильны. Не рекомендуется использовать для production-нагрузок без предварительного тестирования.

🚀 Быстрый старт

  1. Склонируйте репозиторий
    git clone https://github.com/Liis17/BarkFluff.git
cd BarkFluff
  2. Настройте переменные окружения

    Скопируйте файл .env.example в .env и настройте параметры:

    cp .env.example .env

    Отредактируйте .env файл, указав ваши параметры:

    # Доменное имя
DOMAIN=barkfluff.example.com

# Секретные ключи
JWT_SECRET=your-super-secret-jwt-key-min-32-chars
DB_PASSWORD=secure-database-password
MINIO_ROOT_USER=minioadmin
MINIO_ROOT_PASSWORD=secure-minio-password

# Email для SSL уведомлений
SSL_EMAIL=admin@example.com
  3. Запустите Docker Compose
    docker-compose up -d

    Первый запуск может занять несколько минут для инициализации баз данных и загрузки образов.

  4. Проверьте статус сервисов
    docker-compose ps

    Все сервисы должны быть в статусе healthy или running.

  5. Создайте первого пользователя

    Откройте браузер и перейдите по адресу https://your-domain.com

    Нажмите "Регистрация" и создайте первую учетную запись.

Готово!

BarkFluff успешно развернут. Теперь вы можете скачать клиентское приложение и подключиться к вашему серверу.

📁 Структура сервисов

BarkFluff использует микросервисную архитектуру. Вот основные компоненты:

Сервис Порт Описание
API Gateway 443 (HTTPS) Единая точка входа, маршрутизация запросов
Identity Service внутренний Аутентификация, авторизация, управление пользователями
Users Service внутренний Профили пользователей, контакты
Messages Service внутренний Обработка и хранение сообщений
Files Service внутренний Загрузка и хранение файлов (Minio)
Updates Service внутренний Push-уведомления в реальном времени
PostgreSQL 5432 Основная база данных
RabbitMQ 5672 Брокер сообщений для межсервисной коммуникации
Redis 6379 Кеширование, онлайн-статусы
Minio 9000 S3-совместимое объектное хранилище

⚙️ Конфигурация

Основные параметры

Основные настройки находятся в файле .env:

# === Сеть ===
DOMAIN=barkfluff.example.com
HTTPS_ENABLED=true

# === База данных ===
POSTGRES_USER=barkfluff
POSTGRES_PASSWORD=your-secure-password
POSTGRES_DB=barkfluff

# === JWT ===
JWT_SECRET=your-super-secret-key-min-32-characters
JWT_EXPIRY_MINUTES=15
REFRESH_TOKEN_EXPIRY_DAYS=30

# === Minio (файловое хранилище) ===
MINIO_ROOT_USER=minioadmin
MINIO_ROOT_PASSWORD=your-minio-password

# === Redis ===
REDIS_PASSWORD=your-redis-password

# === RabbitMQ ===
RABBITMQ_DEFAULT_USER=rabbitmq
RABBITMQ_DEFAULT_PASS=your-rabbitmq-password

Резервное копирование

Рекомендуется настроить регулярное резервное копирование:

# Создать резервную копию БД
docker-compose exec postgres pg_dump -U barkfluff barkfluff > backup-$(date +%Y%m%d).sql

# Восстановить из резервной копии
docker-compose exec -T postgres psql -U barkfluff barkfluff < backup-20260124.sql

🔧 Управление

Просмотр логов

# Все логи
docker-compose logs -f

# Лог конкретного сервиса
docker-compose logs -f identity-service

Перезапуск сервисов

# Перезапустить все
docker-compose restart

# Перезапустить конкретный сервис
docker-compose restart messages-service

Остановка

# Остановить все сервисы
docker-compose down

# Остановить и удалить данные (осторожно!)
docker-compose down -v

🔐 Безопасность

  • Всегда используйте HTTPS в production
  • Регулярно обновляйте образы Docker
  • Используйте сложные пароли для всех сервисов
  • Настройте firewall и откройте только необходимые порты
  • Регулярно делайте бэкапы базы данных
  • Мониторьте логи на предмет подозрительной активности
Рекомендация

Для production-развертывания рекомендуется использовать reverse proxy (nginx, Traefik) и настроить автоматическое обновление SSL-сертификатов через Let's Encrypt.
