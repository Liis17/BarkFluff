# Этап 3.5 — UX недоступного origin: ошибки, circuit breaker, placeholder-контракт

## Цель

Недоступный/лёжащий origin не превращает скачивание в таймаут-зависание: клиент быстро получает корректный HTTP-код, повторные запросы к мёртвой ноде фейлятся мгновенно (circuit breaker), после восстановления origin всё работает само. Задокументирован placeholder-контракт для клиентов (реализация UI — Фаза 5). Критерий роадмапа: остановленный origin → корректная ошибка, не таймаут-зависание.

## Контекст

- Осознанное следствие модели «всегда с origin»: [../06-files.md](../06-files.md), таблица проблем (№18 из [../09](../09-problems-open-questions.md) — «принято»); снапшот метаданных (3.1) даёт честный placeholder без сети.
- Таймауты/idle-надзор уже заведены в 3.2 (`Federation:S2SConnectTimeout`, `Federation:RemoteFileIdleTimeout`); маппинг gRPC-ошибок в `FetchRemoteFile` — там же. Здесь — доводка до HTTP и устойчивость к повторам.
- Оба клиентских пути скачивания: temp-ветка вложений (3.3) и прямой аватарный маршрут (3.4) — покрываются одинаково.
- Исходящие **события** здесь не трогаем — их ретраи/даунтайм закрыты outbox (Фаза 2).

## Изменение 1 — Federation: circuit breaker per-origin в `FetchRemoteFile`

In-memory (без БД и внешних библиотек; образец простоты — дебаунс 2.9):

- Счётчик подряд идущих **транспортных** неудач per `server_name` (connect-фейл, deadline при установлении, `Unavailable` от сети). `PermissionDenied`/`NotFound` — **не** сбои circuit'а (это ответ живой ноды).
- Порог `N` подряд (конфиг `Federation:RemoteFileCircuitFailures`, дефолт 3) → circuit **open** на `T` (конфиг `Federation:RemoteFileCircuitOpenSeconds`, дефолт 60): `FetchRemoteFile` к этой ноде сразу отвечает `Unavailable` (`origin_circuit_open`), не ходя в сеть.
- По истечении `T` — half-open: один пробный запрос; успех → close (сброс счётчика), неудача → open на новый `T`. Успешный стрим (первый чанк получен) сбрасывает счётчик.
- Метрики: `remote_file_circuit_open{server}` (переходы в open), в `remote_file_fetches{result}` добавить значение `circuit_open`.

## Изменение 2 — Files: карта gRPC → HTTP на fed-скачивании

Единая для обеих fed-веток (3.3 temp, 3.4 прямой):

| Ситуация (gRPC от Federation) | HTTP | Семантика для клиента |
|---|---|---|
| `Unavailable` (origin недоступен / circuit open / idle-таймаут) | **503** + `Retry-After: 30` | «Сервер собеседника недоступен, повторите позже» — временно, ретрай уместен |
| `PermissionDenied` (отказ origin: нет общего чата, privacy аватара) | **404** | «Файл недоступен» — окончательно, не ретраить (намеренно не различаем 403/404 — capability-модель не светит причины) |
| `NotFound` (файл удалён на origin) | **404** | то же |
| Обрыв mid-stream (origin умер во время отдачи, превышение размера) | соединение рвётся (truncated body) | клиент ретраит с `Range` (докачка) |

- Старт ответа только после первого чанка (несёт `Content-Type`/ok-статус): ошибки «до стрима» → чистые коды выше без частично записанного ответа. Убедись, что fed-ветки не пишут заголовки до первого чанка.
- `Retry-After` — конфиг `Files:FedRetryAfterSeconds`, дефолт 30.
- Логи: отказ origin и circuit-open — warning с `server_name`/`file_id` (без содержимого); не спамить error на каждый 503 при лежащей ноде (circuit сам ограничит частоту).

## Изменение 3 — placeholder-контракт для клиентов (документ)

Дописать в [../06-files.md](../06-files.md) раздел «Контракт недоступности для клиентов» (вход для Фазы 5):

1. **Рендер без сети:** сообщение всегда содержит снапшот (`file_name/size/type/preview_file_id/image_width/height`, 3.1) → placeholder рисуется без единого запроса: иконка типа + имя + размер; для картинки — размытый блок размеров width×height.
2. **Выдача ссылки оффлайн-устойчива:** `GetTempDownloadUrl` для fed-ref не ходит на origin (проверка — локальная БД Messages) → ссылка выдаётся всегда; ошибка всплывает только на скачивании.
3. **Коды скачивания:** таблица из Изменения 2: `503 + Retry-After` — «сервер offline, повторить позже» (показать placeholder с кнопкой повтора); `404` — «файл недоступен» окончательно; truncated — ретрай с `Range`.
4. **Превью при недоступном origin отсутствует** (кеш запрещён — решение владельца): лента показывает placeholder'ы; после восстановления origin всё начинает скачиваться само, **никакой ресинхронизации** не требуется (temp-ссылки можно перевыпустить).
5. Старые клиенты: fed-вложение выглядит как «файл не найден» (3.3) — деградация читаемая, плейсхолдер не обещан.

- Ретрай-очередь скачиваний на сервере (ретраит клиент/пользователь); персистентный circuit (in-memory достаточно — рестарт Files = чистый circuit, это допустимо).
- Изменения outbox/событийной доставки (Фаза 2 закрыла даунтайм для событий).
- Кеш «на время недоступности» — запрещён (README фазы).

## Критерии готовности

1. Стенд, критерий роадмапа: остановить federation (или files+minio) node1 → клиент node2 скачивает fed-файл по temp-ссылке → ответ **503 + Retry-After** за время ≤ connect-timeout + запас (не минутное зависание); несколько повторных скачиваний → circuit open, ответы мгновенные (в логах node2 нет S2S-попыток при open circuit). Поднять node1 → после истечения `T` скачивание работает без каких-либо ручных действий/перевыдачи данных.
2. Privacy-отказ (avatar `None`, 3.4) → 404 быстро и **не** открывает circuit (повторные валидные скачивания других файлов с той же ноды продолжают работать).
3. Обрыв mid-stream (kill files node1 во время скачивания) → клиент видит truncated; повторный запрос с `Range` докачивает остаток после восстановления node1 (байты итогового файла = оригиналу).
4. Юнит-тесты: circuit breaker (open по порогу, half-open пробный, close по успеху, denied не считается сбоем); карта ошибок gRPC→HTTP (все строки таблицы); ответ не начат до первого чанка — зелёные.
5. [../06-files.md](../06-files.md) дополнен «Контрактом недоступности для клиентов». Obsidian: `Backend/Federation.md` (circuit breaker, конфиги), `Backend/Files.md` (карта HTTP-кодов fed-скачивания).
