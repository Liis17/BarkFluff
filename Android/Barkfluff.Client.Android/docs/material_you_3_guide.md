# Material You (Material Design 3) — Полное руководство по тонкостям

## 1. Что такое Material You 3 и главная философия

**Material Design 3** (M3, "Material You") — эволюция дизайн-системы Google, представленная в 2021 году вместе с Android 12. Ключевое отличие от M2: **персонализация через цвет, адаптивность и выразительность**.

Три кита M3:
- **Personal** — пользователь выбирает обои, система генерирует цветовую схему для всего интерфейса (Dynamic Color)
- **Adaptive** — единый дизайн для телефона, планшета, фолдабла, десктопа, ТВ
- **Expressive** — большие, смелые элементы, округлые формы, яркие акценты

## 2. Цветовая система (Color System)

### Dynamic Color — главная инновация M3
Система генерирует 5 ключевых палитр из одного seed-цвета (обоев пользователя):
- **Primary** — основной цвет действий, кнопок
- **Secondary** — для менее акцентированных элементов
- **Tertiary** — контрастный акцент для баланса
- **Neutral** — фон, поверхности, текст
- **Neutral Variant** — поверхности с оттенком

### Цветовые роли (Color Roles)
Каждая палитра порождает пары: `Color` + `OnColor` + `ColorContainer` + `OnColorContainer`:

| Роль | Назначение |
|---|---|
| `Primary` | Ключевые кнопки, FAB, активные состояния |
| `OnPrimary` | Текст/иконки поверх Primary |
| `PrimaryContainer` | Фон для акцентных контейнеров |
| `OnPrimaryContainer` | Содержимое в PrimaryContainer |
| `Secondary` | Чипы, фильтры, вторичные действия |
| `Tertiary` | Контрастный акцент |
| `Surface` | Фоны карточек, листов, диалогов |
| `SurfaceVariant` | Альтернативный поверхностный цвет |
| `SurfaceTint` | Наложение Primary для elevation |
| `Outline` | Границы полей ввода, разделители |
| `OutlineVariant` | Ослабленные разделители |
| `Error` / `OnError` | Ошибки |
| `Scrim` | Затемнение под модальными |

### Elevation через цвет (не только тени)
В M3 **elevation выражается цветовым оверлеем** (surface tint), а не только тенями. Чем выше elevation — тем больше Primary-оттенка на поверхности:
- Level 0: `Surface`
- Level 1: Surface + 5% Primary
- Level 2: Surface + 8% Primary
- Level 3: Surface + 11% Primary
- Level 4: Surface + 12% Primary
- Level 5: Surface + 14% Primary

### Светлая и тёмная темы
Обе темы генерируются автоматически из той же палитры. Правило: в тёмной теме `Primary` становится **светлее** (чтобы обеспечить контраст на тёмном фоне).

## 3. Типографика (Type System)

### Type Scale — 15 стилей

| Категория | Стиль | Типичный размер |
|---|---|---|
| Display | Large / Medium / Small | 57 / 45 / 36 dp |
| Headline | Large / Medium / Small | 32 / 28 / 24 dp |
| Title | Large / Medium / Small | 22 / 16 / 14 dp |
| Body | Large / Medium / Small | 16 / 14 / 12 dp |
| Label | Large / Medium / Small | 14 / 12 / 11 dp |

**Тонкость:** Display используется для крупных заголовков-героев, но НЕ для длинного текста. Body Large — основной читаемый текст.

### Шрифты
- По умолчанию: **Roboto** (Android), но система поддерживает любой шрифт
- В документации используется: **Google Sans** (дисплей), **Google Sans Text** (тело), **Google Sans Mono** (код)
- Параметры определяются через design tokens: `font-family`, `font-size`, `line-height`, `font-weight`, `letter-spacing`

## 4. Форма (Shape System)

M3 определяет **Shape Scale** — 5 уровней скругления:

| Уровень | Значение | Применение |
|---|---|---|
| None | 0dp | Разделители, изображения |
| Extra Small | 4dp | Чипы, поля ввода (углы) |
| Small | 8dp | Меню, снэкбары |
| Medium | 12dp | Карточки |
| Large | 16dp | Боковые листы |
| Extra Large | 28dp | FAB, диалоги |
| Full | 50% | Кнопки-таблетки, аватары |

**Тонкость:** Форма — часть брендинга. Приложения могут переопределить всю shape scale глобально.

## 5. Компоненты M3

### Кнопки (Buttons)
5 видов, выстроенных по иерархии акцента:
1. **Filled** (`Primary`) — главное действие
2. **Filled Tonal** (`SecondaryContainer`) — среднее значение
3. **Outlined** — альтернативное действие
4. **Text** — наименее акцентированное
5. **Elevated** (`Surface` + тень) — в контенте

**FAB (Floating Action Button):** 3 размера (Small / Regular / Large / Extended). FAB всегда `PrimaryContainer`.

### Navigation (Навигация)

| Компонент | Когда использовать |
|---|---|
| **Navigation Bar** (нижняя) | 3–5 пунктов, мобильные (телефон/фолдабл) |
| **Navigation Rail** (боковая) | 3–7 пунктов, планшет/десктоп |
| **Navigation Drawer** | 5+ пунктов, постоянная навигация на широком экране |
| **Tab Row** | Контент одного уровня (не навигация) |

**Тонкость:** Navigation Bar и Navigation Rail взаимозаменяемы по брейкпоинтам — это не просто стиль, а часть адаптивной стратегии.

### Cards (Карточки)
3 вида:
- **Elevated** — тень + surface
- **Filled** — `SurfaceVariant`, без тени
- **Outlined** — рамка `Outline`

### Dialogs
- **Basic dialog** — кнопки выровнены вправо, не более 2
- **Full-screen dialog** — для сложных форм, крестик + «Сохранить»

### Sheets (Листы)
- **Bottom Sheet** (Modal / Standard) — контент снизу, управляется свайпом
- **Side Sheet** — для планшетов и десктопа

## 6. Design Tokens (Дизайн-токены)

### Три уровня токенов
```
Reference tokens → System tokens → Component tokens
```

1. **Reference** — все возможные значения палитры: `md.ref.palette.primary40 = #6750A4`
2. **System** — семантические роли: `md.sys.color.primary = md.ref.palette.primary40`
3. **Component** — конкретные: `md.comp.filled-button.container.color = md.sys.color.primary`

**Тонкость:** Никогда не используйте reference-токены напрямую в компонентах — только system или component. Это обеспечивает корректную смену темы.

## 7. Состояния взаимодействия (Interaction States)

Каждый интерактивный элемент имеет **State Layer** — полупрозрачный оверлей поверх контейнера цвета `OnSurface` или `OnPrimary` и т.д.:

| Состояние | Opacity оверлея |
|---|---|
| Hover | 8% |
| Pressed / Ripple | 12% |
| Focused | 12% |
| Dragged | 16% |
| Disabled (контейнер) | 12% |
| Disabled (контент) | 38% |

**Тонкость:** Ripple-эффект в M3 центрируется на точке касания (не заполняет от центра, как в M2).

## 8. Жесты (Gestures)

| Жест | Действие |
|---|---|
| Tap | Основное действие |
| Double tap | Масштаб или «лайк» |
| Long press | Контекстное меню / drag |
| Swipe (горизонт.) | Навигация между экранами / dismissal |
| Swipe (вертикальн.) | Прокрутка / pull-to-refresh |
| Pinch | Масштаб |
| Drag | Перемещение, reorder |

**Тонкость:** Свайп-для-удаления требует подтверждения (undo), если действие деструктивное.

---

## 9. Ввод (Inputs)

M3 поддерживает несколько типов ввода, которые должны обрабатываться единообразно:
- **Touch** — основной на мобильных, min target 48×48dp
- **Stylus** — точность выше, поддержка давления (Pixel Note)
- **Mouse** — hover-состояния обязательны
- **Keyboard** — фокус-индикаторы, Tab-навигация
- **Gamepad/D-pad** — TV и некоторые устройства

**Тонкость:** Минимальный touch target — 48×48dp, даже если визуальный размер меньше. Используйте padding.

## 10. Выделение (Selection)

- **Checkbox** — множественный выбор в списках
- **Radio button** — единственный выбор из группы
- **Switch** — on/off настройки (не для форм!)
- **Chip (Filter)** — множественный выбор категорий
- **Chip (Input)** — редактируемые теги
- **Slider** — диапазон значений

## 11. Компоновка и лейаут (Layout)

### Брейкпоинты M3

| Класс | Ширина | Устройство |
|---|---|---|
| Compact | 0–599dp | Телефоны (портрет) |
| Medium | 600–839dp | Телефоны (ландшафт), маленькие планшеты |
| Expanded | 840dp+ | Планшеты, фолдаблы (развёрнутые), десктоп |

### Колонки и отступы

| Класс | Колонки | Margin | Gutter |
|---|---|---|---|
| Compact | 4 | 16dp | 16dp |
| Medium | 8 | 24dp | 24dp |
| Expanded | 12 | 24dp | 24dp |

### Pane Layouts (многопанельная компоновка)
- **Single pane** — Compact
- **List-Detail** — список слева + детали справа (Expanded)
- **Supporting pane** — основной контент + вспомогательная панель
- **Feed** — карточки в сетке

### Canonical Layouts (каноничные шаблоны)
1. **List-Detail** — почта, контакты
2. **Supporting Panel** — документы с боковой панелью
3. **Feed** — новости, фотографии

**Тонкость:** Navigation Rail + List-Detail = стандарт для Medium/Expanded. Не используйте Navigation Bar на Expanded-экранах.

## 12. Адаптивный дизайн (Adaptive Design)

### Принципы
- **Continuity** — переходы между размерами плавные, элементы «переезжают», а не исчезают
- **Flexibility** — контент масштабируется, колонки добавляются
- **Contextual** — разные экраны — разные сценарии использования

### Фолдаблы
Особый класс: Inner / Outer экран + шарнир. Приложение должно:
- Реагировать на `FoldingFeature`
- Не располагать важный контент на линии сгиба
- Использовать таблет-лейаут при развёрнутом состоянии

## 13. Реализация по платформам

### Android — MDC-Android (View system)
```gradle
implementation 'com.google.android.material:material:1.11.0'
```
- Наследуйте от `Theme.Material3.*`
- Используйте `MaterialTheme` атрибуты (`colorPrimary`, `colorSurface` и т.д.)
- Компоненты: `MaterialButton`, `MaterialCardView`, `BottomNavigationView`, `NavigationRailView`

### Android — Jetpack Compose
```kotlin
implementation 'androidx.compose.material3:material3:1.2.0'
```
- `MaterialTheme { colorScheme, typography, shapes }`
- Dynamic Color: `dynamicDarkColorScheme(context)` / `dynamicLightColorScheme(context)` (Android 12+)
- Компоненты: `Button`, `Card`, `NavigationBar`, `NavigationRail`, `ModalBottomSheet`

**Тонкость Compose:** Используйте `MaterialTheme.colorScheme.primary` вместо hardcoded цветов — это обеспечит поддержку Dynamic Color и пользовательских тем.

### Flutter
```yaml
dependencies:
  flutter:
    sdk: flutter
  # Material 3 встроен в Flutter 3.x
```
- `useMaterial3: true` в `ThemeData`
- `ColorScheme.fromSeed(seedColor: color)`
- Dynamic Color через пакет `dynamic_color`

### Web — Material Web
```bash
npm install @material/web
```
- Custom Elements: `<md-filled-button>`, `<md-card>`, `<md-navigation-bar>`
- CSS custom properties для токенов
- **Статус (2024):** стабильные компоненты: кнопки, чипы, диалоги, FAB, иконки, списки, навигация, прогресс, радио, рейтинг, поиск, выбор, слайдер, переключатель, вкладки, поля ввода

## 14. Кастомизация (Customization)

### Material Theme Builder
Инструмент Google для генерации темы: выбираешь seed-цвет → получаешь все 30+ цветовых ролей, экспортируешь в Compose/XML/CSS/Figma.

### Уровни кастомизации
1. **Seed color** — минимальный, всё остальное генерируется
2. **Color scheme** — ручная настройка отдельных ролей
3. **Typography** — замена шрифта и scale
4. **Shape** — изменение скруглений
5. **Component-level** — переопределение токенов конкретного компонента

**Тонкость:** При ручной настройке всегда проверяйте контрастность пар `Color`/`OnColor` — минимум 4.5:1 по WCAG AA.

## 15. Доступность (Accessibility / Usability)

### Ключевые требования
- **Touch targets** >= 48×48dp
- **Контраст текста** >= 4.5:1 (обычный), >= 3:1 (крупный >= 18pt или >= 14pt bold)
- **Контраст UI-элементов** >= 3:1
- **Focusable elements** — видимый фокус-индикатор (M3 использует `Outline` цвет)
- **Content descriptions** для иконок без подписей
- **Не полагайтесь только на цвет** — добавляйте иконки/текст для передачи смысла
- **Шрифтовое масштабирование** — поддержка до 200% без потери функциональности

### Alt text (доступность изображений)
- Декоративные изображения — пустой contentDescription (`""`)
- Информационные — краткое, точное описание содержимого (не «картинка»)
- Иконки-кнопки — описание действия, не внешнего вида («Удалить», а не «Мусорная корзина»)

## 16. Контент и UX-writing

### Принципы
- **Краткость** — одна мысль, минимум слов
- **Ясность** — простые слова, активный залог
- **Полезность** — говорите, что делать, а не что произошло
- **Последовательность** — одни и те же слова для одних и тех же действий

### Правила для кнопок
- Глагол + объект: «Сохранить файл», «Открыть настройки»
- НЕ: «OK», «Да», «Нет» — непонятно без контекста
- Негативные действия: «Отмена» (не «Нет»)

### Уведомления
- Заголовок: суть события (без «Уведомление о...»)
- Тело: контекст + действие
- Не использовать для маркетинга без явного согласия
- Группировка: несколько от одного приложения → summary notification

### Глобальное письмо (i18n)
- Не вшивайте строки в код — всегда resource files
- Учитывайте RTL-языки (Arabic, Hebrew): зеркалите layout
- Иконки направления (стрелки, шевроны) зеркалируются в RTL
- Иконки без направления (иконка сохранения, сердце) — не зеркалируются
- Формат дат/чисел — системный локаль, не hardcode

## 17. Взаимодействие (Interaction Principles)

### Состояния компонентов
Каждый компонент должен визуально отображать:
- **Enabled** — обычное состояние
- **Hovered** — +8% state layer (mouse)
- **Focused** — +12% + focus ring
- **Pressed** — +12% + ripple
- **Dragged** — +16%
- **Disabled** — 38% opacity контента, 12% opacity контейнера

**Тонкость:** `Disabled` != `invisible`. Пользователь должен видеть, что элемент существует, но недоступен — не скрывайте через `gone`/`display:none`.

## 18. Глоссарий ключевых терминов

| Термин | Определение |
|---|---|
| **Dynamic Color** | Генерация цветовой схемы из обоев пользователя |
| **Color Role** | Семантическое назначение цвета (primary, surface и т.д.) |
| **Tonal Palette** | 13-шаговая шкала оттенков одного цвета |
| **State Layer** | Полупрозрачный оверлей для визуализации состояний |
| **Elevation** | Визуальная высота элемента (в M3 — через цвет + тень) |
| **Shape Scale** | Уровни скругления углов компонентов |
| **Type Scale** | Система типографических стилей |
| **Design Token** | Именованная переменная дизайн-системы |
| **Canonical Layout** | Рекомендованный шаблон компоновки для типичных сценариев |
| **Adaptive Layout** | Лейаут, меняющийся в зависимости от размера экрана |
| **Breakpoint** | Пороговая ширина экрана для смены лейаута |
| **Pane** | Независимая область контента в многопанельном лейауте |
| **Scrim** | Полупрозрачный слой, блокирующий фоновый контент |
| **FAB** | Floating Action Button — главное действие экрана |
| **Seed Color** | Базовый цвет для генерации Dynamic Color палитры |

## 19. Важные тонкости и частые ошибки

1. **Не используйте Navigation Bar на планшете** — только Navigation Rail или Drawer
2. **Dynamic Color доступен только на Android 12+** — всегда делайте fallback-тему
3. **SurfaceTint не равен elevation-shadow** — оба нужны, они дополняют друг друга
4. **Tertiary — не для decoration** — он нужен для баланса и акцента, не для красоты ради красоты
5. **Disabled элементы остаются видимыми** — не скрывайте через `gone`/`display:none`
6. **State layer накладывается на container color**, а не на background — учитывайте в кастомных компонентах
7. **В RTL-языках** — логические отступы (`start`/`end`) вместо `left`/`right`
8. **Минимальный touch target 48dp** — даже для иконок 24dp используйте padding
9. **Не hardcode цвета** — всегда `MaterialTheme.colorScheme.*` или CSS custom properties
10. **Font scale** — тестируйте при 130% и 200% — M3 не гарантирует, что всё поместится, но функциональность должна сохраняться
